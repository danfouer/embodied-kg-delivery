# 能力图谱设计 · 以能力为中枢的本体结构

本文件确立本项目图谱的**最终目标形态：能力图谱（Capability Graph）**，替代此前"知识图谱 → 通用本体库数仓"的定位。能力图谱的中心是**能力**而非知识——知识、技术、赛事、案例、实验、评分口径全部围绕能力组织，每条边回答同一个教学问题：**这项能力是如何通过知识或技术来呈现、训练、应用、测量的**。

## 一、目标对齐

- **总目标**：强化学生在具身智能领域的**应用能力**与**工程能力**。
- **建库目的**：告诉学生或读者，**具体的能力是如何通过知识或者技术来呈现的**——不是罗列知识，而是把"能力"作为可见、可查、可追踪的中枢，让学习者看清"学什么知识/技术 → 形成什么能力 → 能力如何被应用与检验"。

## 二、能力图谱与知识图谱的本质区别

| 维度 | 知识图谱（当前形态） | 能力图谱（目标形态） |
|---|---|---|
| 中心实体 | 文档 / 知识 | **能力** |
| 组织逻辑 | 按文档结构聚合（contains 树） | 按能力组织，知识/技术围绕能力 |
| 边的含义 | 父节点包含子节点（结构关系） | **能力如何被呈现/训练/应用/测量**（教学关系） |
| 回答的问题 | "知识在哪、怎么检索" | "这项能力如何通过知识/技术呈现" |
| 对学习者的价值 | 定位原文 | 看清能力的来龙去脉，支撑应用与工程能力培养 |

**一句话**：知识图谱告诉学习者"知识在哪里"；能力图谱告诉学习者"能力从哪来、怎么练、怎么用"。

## 三、核心实体（围绕能力的本体结构）

### 3.1 能力（Capability）——图谱中枢

能力是图谱的核心实体，所有其他实体通过关系挂接到能力上。能力分两个维度，对应"应用能力 + 工程能力"的双目标：

- **应用能力**：知识/技术转化为"能做什么"——感知、决策、控制、操作等。
- **工程能力**：能力转化为"如何交付"——系统接入、代码实现、算力调度、Sim-to-Real 工程、复现交付等。

能力实例按 **MECE 9 能力域**组织（能力分类骨架），每个能力域下可细分具体能力项。

### 3.2 其余实体（能力的呈现与支撑）

| 实体 | 角色 | 与能力的关系 |
|---|---|---|
| **能力域（CapabilityDomain）** | 能力的分类骨架（MECE 9 域） | 能力归属于能力域 |
| **知识模块（KnowledgeModule）** | 呈现能力的"知识"侧（教材章节） | 知识**呈现**能力 |
| **技术（Technology）** | 呈现能力的"技术"侧（PID/YOLO/VLA/强化学习/域随机化等） | 技术**呈现**能力 |
| **赛事（Competition）** | 能力的应用与检验场景（IVFC2026、蚂蚁灵波） | 能力**应用于**赛事 |
| **案例/实验（CaseStudy/Lab）** | 能力的训练与演示载体 | 能力**通过**案例/实验训练 |
| **评分口径（Metric）** | 能力的测量方式（s_total、S_total、通过率） | 能力**被**评分口径测量 |

## 四、核心关系（能力的呈现逻辑）

能力图谱的核心关系是 **"呈现（presents）"**——这是"告诉学习者能力如何通过知识/技术呈现"的直接承载。

### 4.1 主关系：呈现

| 关系 | 方向 | 含义 | 教学问题 |
|---|---|---|---|
| **知识 呈现 能力** | KnowledgeModule → Capability | 通过学习某知识模块形成/理解某能力 | 这项能力要靠哪些知识来呈现？ |
| **技术 呈现 能力** | Technology → Capability | 通过掌握某技术形成某能力 | 这项能力要靠哪些技术来呈现？ |

### 4.2 支撑关系（能力的全生命周期）

| 关系 | 方向 | 含义 | 教学问题 |
|---|---|---|---|
| **能力 应用于 赛事** | Capability → Competition | 能力在真实赛事中被应用与检验 | 这项能力在赛事里怎么用？ |
| **能力 通过 案例/实验 训练** | Capability → CaseStudy/Lab | 能力通过案例/实验来训练 | 这项能力怎么练？ |
| **能力 被 评分口径 测量** | Capability → Metric | 能力的达成度被评分口径量化 | 这项能力怎么衡量？ |
| **知识 支撑 技术** | KnowledgeModule → Technology | 知识是掌握技术的基础 | 学什么知识才能掌握该技术？ |
| **技术 支撑 能力** | Technology → Capability | 技术是形成能力的抓手 | 掌握什么技术才能形成该能力？ |
| **能力 归属 能力域** | Capability → CapabilityDomain | 能力在 MECE 体系中的分类 | 这项能力属于哪个领域？ |

**呈现链（能力图谱的核心叙事）**：

```
知识模块 ──呈现──▶ 能力 ──应用于──▶ 赛事
   │                ▲  │
   └─支撑─▶ 技术 ──┘  ├──通过──▶ 案例/实验（训练）
                     └──被测量──▶ 评分口径（测量）
```

这条链就是"告诉学习者能力如何通过知识/技术呈现"的完整闭环：**知识/技术是因，能力是果；赛事/案例是应用与训练，评分口径是测量。**

## 五、现有语料如何映射到能力图谱

现有语料天然就是能力图谱的原材料，无需从零造数据，只需按能力重新组织与显式建模：

| 现有语料 | 在能力图谱中的角色 | 映射方式 |
|---|---|---|
| `03-MECE能力体系/MECE能力体系总览.md` | 能力域骨架（9 域）+ 能力定义 | 直接实体化，作为能力分类 |
| `04-赛事知识映射/`（IVFC2026、蚂蚁灵波映射总表） | 知识模块呈现能力、能力应用于赛事 | 映射表的"能力域—知识模块—教材"列直接转为"知识呈现能力"关系 |
| `01-赛事目标/`（赛事能力要求、决赛能力项） | 能力应用于赛事、能力被评分口径测量 | 赛事能力项实体化，挂"应用于赛事"关系 |
| `02-教材精华/`（各教材章节） | 知识模块 | 教材章节作为知识模块，挂"呈现能力"关系 |
| 技术术语（PID、YOLO、VLA、强化学习、域随机化、offset 补偿等） | 技术实体 | 从语料中提炼技术实体，挂"技术呈现能力"关系 |
| `00-总纲/`（使用案例） | 案例/实验 | 案例作为能力训练载体，挂"通过案例训练"关系 |
| 评分口径（s_total、S_total、通过率） | 评分口径 | 作为能力测量方式，挂"被测量"关系 |

**关键结论**：语料中的能力事实已经充分，能力图谱的瓶颈不在数据，而在**把散落在文本/表格中的能力关系显式建模出来**——这正是本体层要做的工作。

## 六、与"本体库数仓底座"评估的关系

能力图谱是本体库的具体实例化，且更具教学针对性：

- **定位收敛**：此前评估的"通用本体库数仓"是技术底座，能力图谱是这一底座上的**目标应用形态**——底座提供类/关系/约束/版本治理，能力图谱是其上承载的、以能力为中枢的语义网络。
- **中枢明确**：通用本体未指定中心实体，能力图谱把**能力**明确为中枢，所有关系围绕能力展开，教学语义清晰。
- **目标对齐**：能力图谱直接对齐"强化应用能力与工程能力"的目标，每条边都服务于这个目标，避免本体建设脱离教学目的。
- **沿用既有评估**：本体库评估中的类/关系设计、版本治理、问数、可视化、安全可控结论**全部适用**，只需把实体清单与关系重心调整为"能力为中枢"。

## 七、落地路径（能力图谱建设三步）

1. **第一步：能力实体化（建模）**
   - 以 MECE 9 能力域为骨架，将能力域、能力项实体化；
   - 定义"呈现/应用于/通过/被测量/支撑/归属"六类核心关系；
   - 输出能力图谱本体 schema（YAML 驱动），保留 graph.json 文档索引层作为溯源底座。

2. **第二步：关系抽取（从语料到能力）**
   - 从映射总表抽取"知识模块—能力""技术—能力"关系；
   - 从赛事能力要求抽取"能力—赛事"关系；
   - 从评分口径抽取"能力—测量"关系；
   - 人工提炼 + 业务确认 + 版本冻结，禁止声称自动抽取。

3. **第三步：能力图谱呈现（问数与可视化）**
   - 问数：支持"某能力靠哪些知识/技术呈现""某赛事考哪些能力"等能力视角查询；
   - 可视化：以能力为节点、以"呈现/应用/训练/测量"为边渲染能力网络，突出能力的来龙去脉；
   - 对外仍称"知识图谱/能力图谱"，内部本体层自由演进。

## 八、设计要点与边界

- **能力是中枢，不是属性**：能力必须是独立实体，不能降级为知识节点的某个字段，否则无法形成"知识/技术呈现能力"的关系网络。
- **应用能力与工程能力双维标注**：每个能力标注其所属维度（应用/工程），支撑"强化应用能力与工程能力"的双目标。
- **每条边回答教学问题**：新增任何实体或关系，先问"它回答了能力如何呈现/训练/应用/测量中的哪个问题"，答不上的不进图谱。
- **溯源不变**：能力实体与关系仍须携带 source_file / source_location，可回溯到语料原文，保持可核查。
