# 知识图谱使用案例 · 以蚂蚁灵波具身大模型挑战赛参赛路径为例

本案例演示「使用者如何消费这份知识图谱」的完整流程，以蚂蚁灵波具身大模型挑战赛（天池赛题 532514）为贯穿线索。它同时回答两个问题：

- **图谱怎么用**：一个 agent（或人）从零开始，用 `query.py` 把图谱当作索引，回溯语料原文，形成可执行动作。
- **赛事怎么牵引学习**：如何借图谱把「想参赛」翻译成「我该学哪本书的哪一章」。

> 本案例的命令与输出均来自交付包 `embodied-kg-delivery/query.py` 的真实运行结果（图谱 244 节点 / 226 边 / 18 社区，2026-11-18 实测）。节点数量随每日素材收集增长，输出编号与社区编号可能变化，但命令与流程不变。

## 一、核心用法：图谱是索引,原文才是内容

`graph.json` 的节点**不存正文**,只存标签、社区、类型与溯源信息（`source_file + source_location`）。正文在 `knowledge-base/` 的 Markdown 里。因此标准用法永远是三步:

```
search（定位节点） → node（看关联结构） → source（取回原文段落）
```

最后把 `source` 返回的原文喂给大模型,作为回答的事实依据——而不是让模型凭节点标签臆测。

## 二、案例背景：一名学生想参加蚂蚁灵波具身大模型挑战赛

**诉求**：「我想参加蚂蚁灵波具身大模型挑战赛,但我不知道赛事考什么、该学什么、从哪下手。」

下面演示如何只用这份图谱,把模糊诉求拆成可执行的参赛与学习计划。

### 步骤 1｜全局感知：先问图谱有多大、有哪些社区

```bash
python query.py stats
```

真实输出（节选）:

```
节点总数 : 244
边总数   : 226
社区数   : 18 (id: [0..17])
节点类型 : {'page': 18, 'heading': 226}
关系类型 : {'contains': 226}
```

**读法**:18 个 page 对应 18 篇语料,226 个 heading 是各篇的小节;所有边都是 `contains`（父节点包含子节点）,不是语义相似。所以这张图是**文档结构索引**,用来按主题快速找原文,不能拿它直接做语义推理。

### 步骤 2｜定位赛事节点:搜索「蚂蚁灵波」

```bash
python query.py search "蚂蚁灵波"
```

命中 36 个节点（节选）:

| node_id | 标签 | 社区 | 来源 |
|---|---|---|---|
| `01_赛事目标_蚂蚁灵波具身大模型挑战赛` | 蚂蚁灵波具身大模型挑战赛.md | 11 · 蚂蚁灵波具身大模型挑战赛 | 01-赛事目标/… @ L1 |
| `01_赛事目标_蚂蚁灵波具身大模型挑战赛_二_评测口径` | 二、评测口径 | 11 · 蚂蚁灵波具身大模型挑战赛 | 01-赛事目标/… @ L8 |
| `04_赛事知识映射_蚂蚁灵波赛事知识映射` | 蚂蚁灵波赛事知识映射.md | 14 · 蚂蚁灵波具身大模型挑战赛 · 赛事—能力域—知识模块映射 | 04-赛事知识映射/… @ L1 |

**读法**:一次搜索同时命中两个核心社区——社区 11 是「赛事本身讲什么」(目标层),社区 14 是「赛事考什么能力、对应哪本书」(映射层)。这正是图谱的双层结构:**先看赛事,再看能力映射**。此外,本案例文档自身也已入图(社区 9),搜索时会一并命中——这恰好说明「文档入图后自己也能被检索到」,不影响上述双层结构的读法。

### 步骤 3｜锁定关键问题:评测口径

对参赛者而言,第一优先是「怎么算赢」。搜索命中 2 个节点（含本案例文档自身的小节标题，真正承载赛事规则的是第一个）:

```bash
python query.py search "评测口径"
```

```
[01_赛事目标_蚂蚁灵波具身大模型挑战赛_二_评测口径]
  标签 : 二、评测口径
  社区 : 11 - 蚂蚁灵波具身大模型挑战赛
  来源 : 01-赛事目标/蚂蚁灵波具身大模型挑战赛.md @ L8

[00_总纲_知识图谱使用案例_蚂蚁灵波参赛路径_步骤_3_锁定关键问题_评测口径]
  标签 : 步骤 3｜锁定关键问题:评测口径
  社区 : 9 - 二、案例背景：一名学生想参加蚂蚁灵波具身大模型挑战赛
  来源 : 00-总纲/知识图谱使用案例-蚂蚁灵波参赛路径.md @ L60
```

> **关键词选择教训**:直接用 `S_total` 搜索无命中——图谱按标签文本归一化匹配,英文符号串不在标题里。改用中文关键词「评测口径」即可一次定位。**先搜中文术语,必要时换同义词重试**,这是用图谱的实用技巧。

### 步骤 4｜溯源:把原文取回来（关键一步）

节点只是路牌,真正的评测规则在原文里:

```bash
python query.py source "01_赛事目标_蚂蚁灵波具身大模型挑战赛_二_评测口径"
```

取回的原文（来自 `01-赛事目标/蚂蚁灵波具身大模型挑战赛.md` 第二节）:

- **每个任务**上报 `attempts / successes`,分 `clean`（标准场景）与 `randomized`（随机扰动场景）两种设置;
- **最终成绩** `S_total = (S_clean + S_rand) / 2`。

同篇语料第三节还规定了**提交要求**（可继续用 `source` 取回）:需交付 `02_代码材料/`（含 `README.md` / `train.sh` / `eval.sh` / `configs/` / `src/`）,主办方据此复现训练与评测;递进阶段为**初赛评测 → 复现与调优说明 → 真机 Demo**。

**可执行结论**:先把 LingBot-VLA 2.0 在 RoboTwin 2.0 仿真环境跑通最小推理,在 `clean` 场景拿到第一个 `attempts/successes`,再攻坚 `randomized`;提交材料必须完整可复现,否则复现环节直接失分——这条规则与 IVFC2026「提交即锁榜」是不同赛事下同构的「提交纪律」。

### 步骤 6｜按「先习而后学」排出学习顺序

蚂蚁灵波的映射文件给出**四阶路径**（比 IVFC2026 多一阶「决赛跃迁」）,可直接作为学习计划:

- **第一阶 · 先参赛（习）**:① 接入 RoboTwin 仿真环境与训练/评测流程,跑通 LingBot-VLA 2.0 最小推理（能力域 1）;② 读懂上面的评测口径（能力域 8）。只需这两项 + 编程基础 L1–L2 入场券即可上手。
- **第二阶 · 按问题补学（学）**:代码写不对补编程基础,VLA 模型理解困难补具身多模态大模型（能力域 6）,双臂操作控制问题补机器人学基础与运动控制（能力域 5）,策略训练困难补机器学习与强化学习（能力域 7）,感知问题补机器人感知与传感（能力域 2）,任务执行不当补决策与任务规划（能力域 4）。
- **第三阶 · 回赛事验证（验）**:把所学知识用到 50 个操作任务,计算 clean/randomized 通过率与 `S_total`,形成「习—学—验」闭环。
- **第四阶 · 决赛跃迁（真机交付）**:进入全真机三任务（抓水果/化妆品入透明盒/倒垃圾）,云端 8×A5000 训练、本地单卡 5080 推理,比的是**真机成功率而非仿真分数**;遇到真机落差,回溯 Sim-to-Real 四大鸿沟与应对策略（offset 补偿、边界框一致性、穷举分布扩充、动态重定位等）,并做好路演复盘。

## 三、案例小结:图谱的正确打开方式

1. **图谱 = 索引,语料 = 内容**:永远 `search → node → source`,用原文而非标签回答。
2. **两层结构**:赛事目标层(社区 11)回答「赛事是什么」,能力映射层(社区 14)回答「该学什么」。
3. **边只读作「包含」**:当前边均为 `contains`,按文档归属理解,别当语义相似度用。
4. **溯源可核**:每条结论都能通过 `source` 回到具体文件的具体行,便于核查与引用。
5. **双语一致**:`python query.py --en search LingBot` 用英文标签搜索,node_id 与中文图谱相同,溯源仍指向中文原文。
6. **关键词用中文术语**:英文符号串（如 `S_total`）直接搜索往往无命中,先搜中文关键词,再换同义词重试。

## 四、给 agent 的一段可复用提示词

```
你在「具身智能赛事知识图谱」交付包目录下。
任务:回答「参加蚂蚁灵波具身大模型挑战赛应该学什么」。
步骤:
1. 运行 python query.py search "蚂蚁灵波" 定位相关节点;
2. 用 python query.py node <node_id> 查看节点所属社区与邻居;
3. 用 python query.py source <node_id> 取回原文小节;
4. 只依据 source 返回的原文作答,并标注来源文件与行号;
5. 若需要英文,用 python query.py --en 前缀,node_id 不变。
禁止:假设节点自带正文;把 contains 边解释为语义相似;用英文符号串（如 S_total）直接搜索。
```
