# 知识图谱使用案例 · 以 IVFC2026 参赛路径为例

本案例演示「使用者如何消费这份知识图谱」的完整流程，以 2026 中国智能车未来挑战赛（IVFC2026）为贯穿线索。它同时回答两个问题：

- **图谱怎么用**：一个 agent（或人）从零开始，用 `query.py` 把图谱当作索引，回溯语料原文，形成可执行动作。
- **赛事怎么牵引学习**：如何借图谱把「想参赛」翻译成「我该学哪本书的哪一章」。

> 本案例的命令与输出均来自交付包 `embodied-kg-delivery/query.py` 的真实运行结果（图谱 231 节点 / 214 边 / 17 社区，2026-11-18 实测）。节点数量随每日素材收集增长，输出编号与社区编号可能变化，但命令与流程不变。

## 一、核心用法：图谱是索引,原文才是内容

`graph.json` 的节点**不存正文**,只存标签、社区、类型与溯源信息（`source_file + source_location`）。正文在 `knowledge-base/` 的 Markdown 里。因此标准用法永远是三步:

```
search（定位节点） → node（看关联结构） → source（取回原文段落）
```

最后把 `source` 返回的原文喂给大模型,作为回答的事实依据——而不是让模型凭节点标签臆测。

## 二、案例背景：一名学生想参加 IVFC2026

**诉求**：「我想参加 IVFC2026,但我不知道赛事考什么、该学什么、从哪下手。」

下面演示如何只用这份图谱,把模糊诉求拆成可执行的参赛与学习计划。

### 步骤 1｜全局感知：先问图谱有多大、有哪些社区

```bash
python query.py stats
```

真实输出（节选）:

```
节点总数 : 231
边总数   : 214
社区数   : 17 (id: [0..16])
节点类型 : {'page': 17, 'heading': 214}
关系类型 : {'contains': 214}
```

**读法**:17 个 page 对应 17 篇语料,214 个 heading 是各篇的小节;所有边都是 `contains`（父节点包含子节点）,不是语义相似。所以这张图是**文档结构索引**,用来按主题快速找原文,不能拿它直接做语义推理。

### 步骤 2｜定位赛事节点:搜索「IVFC2026」

```bash
python query.py search "IVFC2026"
```

命中 30 个节点（节选）:

| node_id | 标签 | 社区 | 来源 |
|---|---|---|---|
| `04_赛事知识映射_ivfc2026赛事知识映射` | IVFC2026赛事知识映射.md | 14 · IVFC2026 · 赛事—能力域—知识模块映射 | 04-赛事知识映射/… @ L1 |
| `04_赛事知识映射_ivfc2026赛事知识映射_ivfc2026_赛事_能力域_知识模块映射` | IVFC2026 · 赛事—能力域—知识模块映射 | 14 | @ L1 |
| `01_赛事目标_ivfc2026中国智能车未来挑战赛_五_评分口径` | 五、评分口径 | 15 · IVFC2026 · 中国智能车未来挑战赛 | 01-赛事目标/… @ L35 |

**读法**:一次搜索同时命中两个核心社区——社区 15 是「赛事本身讲什么」(目标层),社区 14 是「赛事考什么能力、对应哪本书」(映射层)。这正是图谱的双层结构:**先看赛事,再看能力映射**。此外,本案例文档自身也已入图(社区 8),搜索时会一并命中——这恰好说明「文档入图后自己也能被检索到」,不影响上述双层结构的读法。

### 步骤 3｜锁定关键问题:评分口径

对参赛者而言,第一优先是「怎么算赢」。搜索命中 2 个节点（含本案例文档自身的小节标题，真正承载赛事规则的是第一个）:

```bash
python query.py search "评分口径"
```

```
[01_赛事目标_ivfc2026中国智能车未来挑战赛_五_评分口径]
  标签 : 五、评分口径
  社区 : 15 - IVFC2026 · 中国智能车未来挑战赛
  来源 : 01-赛事目标/IVFC2026中国智能车未来挑战赛.md @ L35

[00_总纲_知识图谱使用案例_ivfc2026参赛路径_步骤_3_锁定关键问题_评分口径]
  标签 : 步骤 3｜锁定关键问题:评分口径
  社区 : 8 - 二、案例背景：一名学生想参加 IVFC2026
  来源 : 00-总纲/知识图谱使用案例-IVFC2026参赛路径.md @ L60
```

### 步骤 4｜溯源:把原文取回来（关键一步）

节点只是路牌,真正的评分规则在原文里:

```bash
python query.py source "01_赛事目标_ivfc2026中国智能车未来挑战赛_五_评分口径"
```

取回的原文要点（来自 `01-赛事目标/IVFC2026中国智能车未来挑战赛.md` 第五节）:

- 两个赛段:`pre`（线上预赛）、`final`（现场决赛）,各自计通过率;
- 五级任务 L1–L5,任务通过率 = `successes / attempts`;
- 赛段均分 = 5 个等级通过率的平均;`s_total` = 两赛段均分的平均,即榜单排名键;
- 每个单元格 `{"attempts": N, "successes": M}`,以本地 Controller 报告为准;
- 榜单取每条路线最优 `s_total`,**提交即锁定,不可覆盖、不可删除**。

**可执行结论**:先把最小可运行算法跑通 L1,拿到第一个 `successes/attempts`,再去刷 L2–L5;不要一上来就提交不成熟的 `s_total`,因为提交即锁榜。

### 步骤 6｜按「先习而后学」排出学习顺序

映射文件给出三阶路径,可直接作为学习计划:

- **第一阶 · 先参赛（习）**:① 接入 CARLA + SDK,跑通最小算法（能力域 1）;② 读懂上面的评分口径（能力域 8）。只需要这两项 + 编程基础 L1–L2 入场券即可上手。
- **第二阶 · 按问题补学（学）**:跑不通补编程基础,感知不行补第 2/3 章,定位漂移补第 6/7 章,决策/轨迹不安全补第 5/9/10 章,策略学习补机器学习与强化学习（DQN）。
- **第三阶 · 回赛事验证（验）**:把学到的知识用到 L1–L5,算通过率、看 `s_total`,形成「习—学—验」闭环。

## 三、案例小结:图谱的正确打开方式

1. **图谱 = 索引,语料 = 内容**:永远 `search → node → source`,用原文而非标签回答。
2. **两层结构**:赛事目标层(社区 15)回答「赛事是什么」,能力映射层(社区 14)回答「该学什么」。
3. **边只读作「包含」**:当前边均为 `contains`,按文档归属理解,别当语义相似度用。
4. **溯源可核**:每条结论都能通过 `source` 回到具体文件的具体行,便于核查与引用。
5. **双语一致**:`python query.py --en search IVFC` 用英文标签搜索,node_id 与中文图谱相同,溯源仍指向中文原文。

## 四、给 agent 的一段可复用提示词

```
你在「具身智能赛事知识图谱」交付包目录下。
任务:回答「参加 IVFC2026 应该学什么」。
步骤:
1. 运行 python query.py search "IVFC2026" 定位相关节点;
2. 用 python query.py node <node_id> 查看节点所属社区与邻居;
3. 用 python query.py source <node_id> 取回原文小节;
4. 只依据 source 返回的原文作答,并标注来源文件与行号;
5. 若需要英文,用 python query.py --en 前缀,node_id 不变。
禁止:假设节点自带正文;把 contains 边解释为语义相似。
```
