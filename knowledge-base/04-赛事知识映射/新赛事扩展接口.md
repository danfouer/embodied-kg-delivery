# 新赛事扩展接口

本知识图谱的核心设计目标之一是**保留面向新赛事的接口**：当新的赛事出现、需要新的知识时，可以随时补充进来，而无需推倒重建既有图谱。

## 一、扩展原则

图谱采用「赛事目标 → 能力域 → 知识模块」的三级结构，新赛事的接入遵循以下原则：

1. **复用优先**：新赛事所需的能力，优先复用已有的 8 个能力域。只有当新赛事出现全新能力类型时，才新增能力域。
2. **增量补充**：新赛事新增的知识点，在 `02-教材精华/` 或新建教材文件中补充，在 `04-赛事知识映射/` 中建立映射，既有节点与边不受影响。
3. **保持 MECE**：新增能力域或知识模块时，仍需满足相互独立、完全穷尽的约束，不与既有域重叠。
4. **图谱自动并入**：补充语料后重新运行 graphify，新赛事知识自动并入图谱，`graph.json` 增量更新。

## 二、扩展操作步骤

当出现新赛事时，按以下步骤扩展：

### 步骤 1：登记赛事目标
在 `01-赛事目标/` 目录下新建文件，命名如 `<赛事名称>.md`，内容包括：
- 赛事概况（全称、赛程、官网）。
- 赛题与平台（平台、传感器/模型、任务规模）。
- 评分口径（任务分级、通过率计算、排名规则）。
- 对参赛者的能力要求（赛事牵引的能力域）。

### 步骤 2：评估能力域
对照 `03-MECE能力体系/MECE能力体系总览.md` 中的 8 个能力域，判断：
- 新赛事的能力是否已被现有能力域覆盖？
- 是否需要新增能力域？如需，在总览中追加，保持 MECE。

### 步骤 3：建立知识映射
在 `04-赛事知识映射/` 下新建文件，命名如 `<赛事名称>赛事知识映射.md`，包含：
- **映射总表**：能力域 → 赛事能力项 → 需学习的知识模块 → 来源教材。
- **先习而后学路径**：第一阶（直接动手）、第二阶（按问题回溯知识）、第三阶（验证迭代）。

### 步骤 4：补充知识模块（如需）
若新赛事涉及现有六本教材未覆盖的知识，在 `02-教材精华/` 补充相应知识模块，或新建教材精华文件。

### 步骤 5：重建图谱
在知识库根目录重新运行 graphify，新赛事知识自动并入 `graph.json`：

```
graphify <知识库根目录> --force
```

使用 `--force` 确保新图谱被写入（新增节点会使图谱变大，通常无需 `--force`，但首次重建或结构调整时使用更稳妥）。

## 三、扩展示例（假设新增「无人机自主导航挑战赛」）

1. **登记**：`01-赛事目标/无人机自主导航挑战赛.md`——登记赛事概况、赛题（无人机仿真导航）、评分口径。
2. **能力域评估**：复用能力域 1（系统接入）、2（感知融合）、4（决策规划）、5（运动控制）、7（策略学习）、8（仿真验证）；如需「飞行动力学」可新增能力域 9。
3. **建立映射**：`04-赛事知识映射/无人机赛事知识映射.md`——映射到教材中的导航规划、运动控制、感知等知识模块。
4. **补充知识**：若需飞行动力学，在 `02-教材精华/` 补充。
5. **重建图谱**：运行 graphify，新赛事节点与边并入，既有节点保持。

## 四、接口的可查询性

扩展后的新赛事可直接通过 graphify 查询：
- `graphify query "新赛事需要哪些知识"`——BFS 遍历返回相关能力域与知识模块。
- `graphify path "新赛事" "某知识模块"`——追踪赛事到知识模块的最短路径。
- `graphify explain "新赛事"`——解释该赛事节点及其邻居。

新赛事与既有赛事、能力域、知识模块之间的关联关系，全部在图谱中可追溯、可查询。
