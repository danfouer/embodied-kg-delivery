# 蚂蚁灵波具身大模型挑战赛

## 一、赛事概况

- **赛事名称**：蚂蚁灵波具身大模型挑战赛（天池赛题 532514）。
- **核心任务**：基于 **LingBot-VLA 2.0** 视觉-语言-动作模型，在 **RoboTwin 2.0 · Aloha-AgileX** 双臂机器人仿真/真机环境下，完成 **50 个操作任务**的具身智能训练与评测。

## 二、评测口径

- **每个任务**上报 `attempts / successes`，分 `clean`（标准场景）与 `randomized`（随机扰动场景）两种设置。
- **最终成绩** `S_total = (S_clean + S_rand) / 2`。

## 三、提交要求

需交付 `02_代码材料/`（含 `README.md` / `train.sh` / `eval.sh` / `configs/` / `src/`），主办方据此复现训练与评测流程。

**递进阶段**：初赛评测 → 复现与调优说明 → 真机 Demo。

## 四、模型与环境

- **模型**：LingBot-VLA 2.0，视觉-语言-动作（VLA）模型，6B 参数量级。
- **仿真环境**：RoboTwin 2.0，双臂 Aloha-AgileX 构型。
- **任务规模**：50 个操作任务，覆盖双臂精细操作。

## 五、对参赛者的能力要求（赛事牵引的能力域）

蚂蚁灵波具身大模型挑战赛要求参赛者具备以下能力域（与 `03-MECE能力体系/` 对应）：

1. **具身大模型理解与运用能力**：理解视觉-语言-动作（VLA）模型的原理，能加载、推理与微调 LingBot-VLA 2.0。
2. **机器人本体与运动学能力**：理解双臂机器人构型、运动学、动力学，能完成仿真到真机的映射。
3. **感知与多模态融合能力**：融合视觉、语言、动作信息，完成操作任务的感知理解。
4. **策略学习与训练能力**：掌握强化学习、行为克隆、模仿学习等策略学习方法，完成操作策略的训练。
5. **数据与训练工程能力**：完成数据获取、血缘校验、低资源训练、评测流程的工程化。
6. **仿真到真机迁移能力**：理解仿真到现实（sim-to-real）的迁移，完成 clean 与 randomized 两种场景的评测。

## 六、决赛阶段（2026-11-16 决赛答辩实录）

决赛阶段从仿真评测进入**全真机实操**，是赛事从「云端训练」走向「物理世界交付」的关键跃迁。以下需求与要求均来自 2026-11-16 决赛答辩实录与《具身智能：从看见到行动》第 6 章「跨越鸿沟」的决赛现场增补素材。

### 6.1 决赛基本配置

- **真机三任务**：抓水果 → 化妆品放入透明化妆盒 → 倒垃圾。全部为真机操作，比的是**真机成功率，不是仿真分数**。
- **算力配置**：云端 **8 张 A5000** 训练，本地 **单卡 5080** 推理——**算力鸿沟也是鸿沟**，训练与推理的算力落差是决赛的硬约束。
- **官方数据**：仅提供 **647 条**公共数据，且每个初始分布只有 **1 张样本**——数据稀缺是决赛的核心痛点。
- **评测方式**：观察团实名投票，每位导师最多支持三支团队，表单仅可提交一次。

### 6.2 决赛对能力域的具体要求

决赛阶段在初赛能力域基础上，进一步细化了以下能力要求：

**① 指令跟随能力（Instruction Following）**
- 抓水果任务中，需在单个 layout 内放置多种水果，模型须准确识别**目标物体**及其**对应颜色的盘子**。
- 需将文本 prompt 与视觉分割掩码（segmentation mask）结合，在训练与推理时同步输入，提升目标识别准确率。
- 失败案例分析：多数失败源于**物体距离远导致可达性不足**或**抓取松脱**，而非识别错误。

**② 训练加速能力**
- 训练优化迁移：将 flash attention、graph 扩展、基于人程的优化等手段落地，将训练从 **15 秒/step 压缩至 4 秒/step**，加速 **3.7 倍**。
- 48 小时内完成 **30 个 checkpoint** 的迭代，实现快速试错。
- 训练不可停：即使 loss 降到低位仍持续训练，并在过程中不断补充新数据。

**③ 推理优化能力**
- **动作平滑**与**执行窗口调整**：一次推理产出 50 个 action，但只执行 16 次，提升推理的平滑性与精细化。
- 低显存推理：6B VLA 模型需在 **8GB 显存**上跑起来（分层推理），但能跑不等于能完成任务。

**④ 数据采集与分布对齐能力**
- **数据稀缺下的扩充策略**：穷举官方数据的初始分布，尽可能覆盖各种物体组合与名称（FDU sonic 队做法）。
- **分布对齐**：采集的数据须与公开数据集**相似分布**，而非泛化的 corner case——采集过泛反而导致分布学习不理想。
- **数据质量优先**：更少量、更高质量、更稳定的数据优于大量低质数据；多人采集习惯差异会引入噪声，需收敛采集规范。
- **逆向采集**：通过逆向读取视频，从任务结束状态反推操作物体，获取带掩码的数据集（SST 队做法）。

**⑤ Sim-to-Real 迁移能力（决赛核心考验）**
决赛现场完整印证了 Sim-to-Real 的**四大鸿沟来源**，每一条都有真实的真机应对：

| 鸿沟来源 | 决赛现场表现 | 应对策略 |
|---|---|---|
| **动力学不精确** | 机械臂带载下坠；同一任务不同负载关节姿态不同 | 推理阶段加 **offset 补偿**（工程师手调，非训练产出）；增加测试数据与 offset 值 |
| **感知差异** | 透明化妆盒受光照影响识别飘移；橘子 vs 橙子靠边界框区分 | 边界框的**颜色与粗细必须与训练一致**；外部模型画框辅助 |
| **分布偏移** | 仿真表现出色、真机手忙脚乱；官方 647 条数据每分布仅 1 张 | **穷举初始分布**扩充数据；自采数据补充（TARS 任务三自采数据夺冠） |
| **动态不确定性** | 物体被碰掉需重新定位；评委严苛程度不同→成绩随机 | 模型动态场景流式更新；路演须放视频，展示与复盘不可缺失 |

**⑥ 视觉提示与分割能力**
- 用**显式视觉提示**作为 System 1 与 System 2 的衔接：解析指令→生成目标物体 prompt→SAM 3 获取掩码→掩码合并到原图→送 VLA 训练推理。
- 掩码内像素保持不变，掩码外像素乘 0.1 淡化干扰物，让 VLA 直接「看到」期望操作的物体。

**⑦ 指令改写与泛化能力**
- 针对数据集中未见的指令，通过**指令改写**增强模型对未见指令的泛化能力。
- 结合公共数据集与自采数据，将指令扩充至 **5000+ 条**；通过**学习率调整**显著提升分数。

**⑧ 真机操作与工程实操能力**
- 真机经验稀缺：首次摸真机导致的操作事故（如移动桌子导致 checkpoint 作废）。
- 数据采集的实操挑战：人手采集效率低、习惯差异大，需双人协作提升采集质量与效率。
- 机械臂底层控制：PD 控制器输入命令与输出状态的选择影响训练一致性；需处理遮挡物与故障自动回退。

### 6.4 决赛核心教训（与第 6 章跨越鸿沟的呼应）

决赛现场为 Sim-to-Real 理论提供了完整的工程实证，核心教训可归纳为：

- **损失下降 ≠ 学会**：动作头训练 100 步，训练 loss 0.43→0.33 在降，但验证集误差 0.34→0.39 在升——剪刀差即过拟合，判定不部署。
- **能跑 ≠ 能完成**：分层推理让 6B VLA 跑在 8GB 显存上，但 400 步达到推理步数上限时任务未成功。
- **内部榜 ≠ 官方成绩**：内部榜 0.72 是占位值，不进任何报告；评测以留出数据的真实表现为准。
- **算力鸿沟也是鸿沟**：训练在云端 8 卡 A5000，推理在本地一张 5080——算力落差直接约束可迭代的模型复杂度。
- **工作流跑完 ≠ 任务通过**：workflow_complete=true、退出码 0、cleanup_ok=true，都不能替代 report.json 中的正式状态判定。
